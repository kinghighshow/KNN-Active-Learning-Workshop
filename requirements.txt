## Summary

We used KNN to classify each hour of 2025 in Waterloo, ON as **Clear, Cloudy, Rain or Snow**, based on temperature, humidity, dew point, pressure, cloud cover, wind, hour and month.

- **Data:** 8,760 hourly records from the [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api), stored in a Neon PostgreSQL table (`knn_weather`). The target comes from the WMO weather code. The columns used to build the target (`weather_code`, `rain`, `snowfall`, `precipitation`) are removed from the features to avoid leakage.
- **Preprocessing:** extracted hour and month features, used a median imputer and `StandardScaler` fitted on the training set only, and made a stratified 80/20 split.
- **Model:** `KNeighborsClassifier`, with k (3–25) and the distance metric tuned by 5-fold cross-validation on macro F1.
- **Results:** best k = 3 (Euclidean). On the test set, 86.7% accuracy and 0.804 macro F1, against 45.1% and 0.155 for a majority-class baseline. Rain and Snow are the hardest classes and are mostly confused with Cloudy. When whole weeks are held out, macro F1 is about 0.61, which we treat as the realistic estimate for unseen weeks.
- **Architecture:** ML Pipeline Pattern: `DataLoader` → `Preprocessor` → `KNNModel` → `Evaluator`, chained by `KNNPipeline`.

## How to run

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt
```

1. Copy `.env.example` to `.env` and set `DATABASE_URL` to your Neon connection string. If you skip this, the notebook uses the cached CSV in `data/`.
2. Open `KNN_Workshop_Solution.ipynb` and choose **Run All**. The first run writes the data to the `knn_weather` table. Later runs read it back from Neon.

The charts are interactive Plotly figures. GitHub's notebook preview doesn't show them, so to see them online, paste the notebook's GitHub link into [nbviewer](https://nbviewer.org/).
